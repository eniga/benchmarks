Cache coherence is the discipline that keeps the many private caches inside a modern processor from disagreeing about the contents of shared memory. Every core in a multicore chip has its own level-one and level-two cache, and any one of them can hold a copy of the same memory location. If two cores both cache the same line and one of them writes to it, the other copy silently becomes stale unless something intervenes. Cache coherence is that intervention: a set of hardware rules that guarantee every cache, at every moment, presents a single well-defined value for each memory location, as though the caches were not there.

The underlying problem is one of visibility and ordering. A write performed by one core must eventually be observed by every other core, and the order in which writes to the same location are observed must be the same for all of them. Without coherence, a program that reads a counter incremented by a sibling core might read a value from long ago, and the bug would depend on timing and scheduling in ways that are hard to reproduce. Coherence removes this whole class of defect so that shared memory is even possible to reason about.

The most widely taught mechanism is the MESI protocol, which attaches a state to every cache line. In the Modified state a line holds the only up-to-date copy of the data and differs from main memory; the owning cache must write it back before anyone else may read it. In the Exclusive state a line is cached in exactly one cache and still matches memory, so it can be promoted to Modified on a write without telling anyone. In the Shared state several caches hold read-only copies that all agree with memory; any one of them may write, but only after invalidating the others. In the Invalid state the line is simply not present. Transitions are triggered by reads, writes, and snoops, interconnect messages that ask other caches to react. When one core writes to a line that another core shares, the coherence logic broadcasts an invalidate; the other copy drops to Invalid, the writer's moves to Modified, and the next read from the other core is forced to fetch the fresh value. This is how one logical value is preserved across many physical copies.

Real machines implement this logic in one of two broad ways. Snoop-based coherence has every cache watch a shared bus or point-to-point interconnect and react to transactions addressed to lines it holds. It is simple and fast for few cores but does not scale well, since traffic grows with the number of participants. Directory-based coherence, used in large chips and NUMA machines, keeps a directory that records which caches hold a copy of each line; the owner consults the directory to find exactly who must be invalidated. Directory schemes scale to many cores and many sockets at the cost of extra state and a little latency. Both are pure hardware and both operate at the granularity of the cache line, typically sixty-four bytes.

It is important to separate coherence from the related but distinct idea of memory consistency. Coherence is a hardware property about a single location: all cores agree on the value and on the order of writes to that location. Consistency is a broader, software-visible contract about the order in which reads and writes to different locations are observed. A system can be perfectly coherent, with every cache agreeing on each line, and still expose a reordering of writes to two different locations that surprises a lock-free algorithm. That is why architectures provide memory barriers and, in weaker models such as ARM and RISC-V, a family of fence instructions and acquire-release semantics. The programmer must use these to impose the ordering the algorithm needs; the hardware coherence protocol will not do it for free.

Several practical issues make coherence a live concern for performance as well as correctness. Store buffers let a core retire a write before it is globally visible, which is essential for throughput but means a core may not immediately see the effect of its own write on a sibling; this is the root of many subtle bugs and the reason a read after a write sometimes needs a barrier. False sharing occurs when two cores write to different variables that happen to sit in the same cache line; the coherence protocol then ping-pongs the line between cores for no logical benefit, collapsing what should be parallel work into a serialized bottleneck, and padding and alignment are the standard remedies. Non-temporal or streaming stores deliberately bypass the cache for bulk copies, trading coherence traffic for bandwidth.

Coherence also extends well beyond the classic CPU. Many-core accelerators, GPUs, and chiplet designs with multiple dies must keep coherence across a much larger and more irregular topology, and interconnects such as ring, mesh, and crossbar networks each impose different latency and bandwidth profiles on coherence traffic. Emerging semantics, fine-grained atomics, and coherence over fabrics such as CXL push the problem into new territory, but the requirement is unchanged: no matter how many caches, cores, or sockets exist, the machine must behave as if there were one memory with one value per location.

In summary, cache coherence is the hardware foundation that makes shared-memory parallelism sane. Protocols like MESI, implemented by snooping or by directories, keep every copy of a line in agreement, while memory-consistency models and barriers handle the ordering of operations across locations. Understanding the boundary between the two, what the hardware guarantees automatically and what the programmer must enforce, is essential for writing concurrent code that is both correct and fast.
